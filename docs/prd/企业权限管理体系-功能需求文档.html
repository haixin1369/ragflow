RAGFlow 企业权限管理体系 · 功能需求文档

版本：v0.3（增补 FR-08 目录结构管理） 日期：2026-11-21 适用对象：RAGFlow 二次开发（Go 后端 + React 前端）

1. 背景与目标

RAGFlow 开源版本的权限模型面向个人与小团队场景：任何登录用户都能浏览、创建知识库，不存在组织维度的隔离，知识库之间默认互通。这无法满足中国企业"多子公司 / 多部门各自管理知识库、权限统一由管理员管控"的要求。

本次二次开发引入三层能力，使知识库从"默认可见"变为"默认不可见、按需授权"：

  1. 组织架构：支持子公司 / 部门层级，用户归属唯一部门，各部门独立管理自己的知识库；
  2. 角色化功能权限：功能权限由系统内置超级管理员通过"角色"统一定义与分配；
  3. 资源级授权：知识库所有者可为其知识库配置可查看 / 可编辑人员，无授权的用户完全不可见该知识库。

证据（客户要求）→ 受影响角色（普通用户、知识库所有者、超级管理员）→ 产品决策（组织隔离 + 角色授权 + 资源授权）→ 可观察结果（无权限者看不到知识库，超管可全局管控）。

2. 角色与对象模型

2.1 角色

角色性质能力边界
超级管理员 系统内置且全系统仅一个账号，不可停用、不可删除、其权限不可编辑 唯一的系统管理入口持有者：维护组织架构与账号、定义角色与功能权限、查看并管控全部知识库（改成员权限、强制转移所有权）。P0
自定义角色 由超管创建，数量不限 一组功能权限的集合。用户被赋予角色后获得对应功能权限；未被赋予任何角色的用户没有任何功能权限。
普通用户 账号由超管创建 归属唯一部门；功能权限由角色决定；对自己拥有的知识库拥有完整控制权（含成员配置）。

2.2 对象

对象定义关键属性
部门 / 子公司 树形组织单元，支持多级层级 名称、上级部门；成员用户；部门下知识库（由创建者归属推导）
用户 登录主体 唯一所属部门（不可多属）；角色（0 或 1 个）；账号由超管创建 / 停用 / 删除
知识库 核心共享资源 唯一所有者（创建者）；归属部门（= 所有者所在部门）；成员授权（可查看 / 可编辑，仅针对个人用户）；多级目录树（文档按目录分类管理，FR-08）

2.3 知识库权限层级

所有者 > 可编辑 > 可查看 > 无权限（不可见）。同一用户在同一知识库上只持有其中一级；层级之间不叠加。

3. 范围

优先级内容
P0组织架构管理（FR-01）、用户账号管理（FR-02）、角色与功能权限管理（FR-03）、知识库创建与归属（FR-04）、知识库成员授权（FR-05）、可见性控制（FR-06）、超管知识库管理（FR-07）、知识库目录结构管理（FR-08）
P1权限变更与所有权转移的审计日志；按部门维度的知识库统计报表
明确排除不引入"部门管理员"中间角色（账号与组织全部由超管管理）；不做授权审批流；不改变 RAGFlow 其他业务功能的行为

4. 功能需求

FR-01 组织架构管理 P0

目的
建立子公司 / 部门层级，作为用户归属与知识库归属的组织依据。
触发者
仅超级管理员，入口在系统管理 → 组织架构。
处理规则
  • 支持新增、重命名、调整上级、删除部门节点，树形展示；
  • 删除约束：部门下仍有在岗用户或归属知识库时，不允许删除，需先转移用户或知识库；
  • 部门节点数量、层级深度不做业务上限。
结果与状态
组织树持久保存；删除为即时生效并要求二次确认。

FR-02 用户账号管理 P0

目的
由超管统一维护企业内全部用户账号及其组织 / 角色归属。
触发者
仅超级管理员，入口在系统管理 → 用户管理。
处理规则
  • 创建用户时必须指定：姓名 / 账号、初始密码、唯一所属部门、角色（可不选）；
  • 支持编辑所属部门与角色、重置密码、停用 / 启用、删除账号；
  • 停用：立即禁止登录，保留账号与其拥有的知识库；
  • 删除：账号名下仍有知识库时阻断删除，须先通过 FR-07 逐一转移所有权；转移完成后方可删除，删除时自动将其从所有知识库的成员授权名单中移除；
  • 用户不可自行修改自己的部门与角色。
异常
内置超管账号不可停用、不可删除；同账号名重复创建时提示冲突。

FR-03 角色与功能权限管理 P0

目的
功能权限统一收口：只有超管能定义角色与分配功能权限，普通用户无法自我提权。
触发者
仅超级管理员，入口在系统管理 → 角色管理。
处理规则
  • 超管可创建任意数量的角色，为每个角色勾选功能权限项；
  • P0 功能权限项：创建知识库；
  • 权限粒度为按钮级（已确认）：每个功能权限项对应到具体操作（如创建知识库、上传文档、创建对话助手等），用户无某项权限时，对应操作按钮不显示，仅能看到自己可执行的操作；完整权限项清单需在实施前与现有功能菜单逐一对齐；
  • 编辑角色权限后，所有持有该角色的用户即时生效；
  • 删除角色时若仍有用户持有该角色，阻断并提示先调整用户。
结果与状态
用户登录后仅看到其功能权限范围内的功能入口；失去权限的功能即时隐藏。

FR-04 知识库创建与归属 P0

目的
将"谁能创建知识库"收敛为功能权限，创建即建立所有权与部门归属。
触发者
被授予"创建知识库"功能权限的用户。
处理规则
  • 创建者自动成为该知识库的所有者；
  • 知识库归属创建者所在部门，归属关系随所有者转移（FR-07）而更新；
  • 无该功能权限的用户看不到任何创建知识库入口。

FR-05 知识库成员授权 P0

目的
所有者自主控制自己知识库的协作者范围与协作深度。
触发者
仅知识库所有者（可编辑人员不能配置成员权限；这是本需求与常见协作系统的关键差异）。
处理规则
  • 所有者在知识库设置 → 成员管理中维护两个名单：可查看人员、可编辑人员；
  • 授权对象为个人用户（支持按姓名 / 账号搜索全部用户，含跨部门用户——已确认允许跨部门授权）；
  • 支持批量添加：可按部门整批导入其全部成员（如添加整个部门的人员）；批量导入后仍逐人落地为个人授权，后续部门成员变动不会自动同步名单，由所有者自行维护；
  • 同一用户在同一知识库只能存在于一个名单；将查看人员升级为编辑（或反之）视为移动，不产生重复授权；
  • 所有者本人不出现在两个名单中，也不能将自己移出所有者身份（所有权变更只能通过 FR-07）；
  • 移除成员即时生效。
异常
授权已被停用 / 已删除的用户时提示不可选；成员名单为空时知识库仅所有者与超管可见。

FR-06 知识库可见性控制 P0

目的
落实"不可查看没权限的知识库"——可见即授权，无授权即不可见。
判定规则（唯一判定口径）
某用户对某知识库可见，当且仅当满足以下任一条件：
  • 该用户是超级管理员；
  • 该用户是该知识库的所有者；
  • 该用户在该知识库的可查看名单中；
  • 该用户在该知识库的可编辑名单中。
部门归属不自动产生可见性（已确认：即使同部门，也一律须经所有者显式授权）。
处理规则
  • 不可见的知识库不出现在知识库列表、搜索结果与任何下拉选择器中；
  • 直接通过 URL / ID 访问不可见知识库时返回"不存在或无权限"，不泄露其存在性；
  • 被移出成员名单后，用户下次访问即被拒绝（不承诺中断进行中的会话）。

FR-07 超管知识库管理 P0

目的
超管对企业内全部知识库拥有最终管控权，覆盖人员调整与所有权纠偏。
触发者
仅超级管理员。
处理规则
  • 超管的知识库列表展示全部知识库（含其无成员授权的），并支持按部门、所有者筛选，列表标注每库的所有者与归属部门；
  • 超管可修改任意知识库的成员名单（增删可查看 / 可编辑人员），规则同 FR-05；
  • 强制转移所有权：超管选择新所有者后二次确认；转移即时生效——新所有者立即获得所有者权限（含成员配置权），知识库归属部门更新为新所有者所在部门；
  • 转移时原所有者的后续权限降为"可查看人员"（已确认）。
异常
新所有者候选为已停用 / 已删除用户时不可选；转移操作失败时回滚，不产生部分生效状态。

FR-08 知识库目录结构管理 P0

目的
支撑上万级文档的知识库：在知识库内建立多级目录树，文档按目录分类上传、浏览与移动，保证大规模文档可组织、可定位。
触发者
目录的新建 / 重命名 / 移动 / 删除与文档上传同权限层级（所有者与可编辑人员，见第 5 章权限矩阵）；可查看人员仅可浏览目录树并按目录查看文档。
处理规则
  • 每个知识库内可建立多级目录树，支持新建、重命名、移动、删除目录；同一父目录下目录名称不得重复；
  • 文档上传时选择目标目录，默认进入根目录（未分类）；每份文档归属唯一目录，可在目录间移动；
  • 目录不产生独立权限：目录内文档的可见性与操作权限完全继承其所在知识库（同 FR-06 判定口径）；
  • 删除目录约束：目录下仍有文档或子目录时阻断删除，须先清空或移走内容，避免大规模误删；
  • 面向上万级文档的规模要求：目录树支持懒加载；文档列表按目录分页展示；支持按文档名称在知识库内全局搜索，搜索结果标注所属目录路径。
结果与状态
知识库详情页采用左侧目录树 + 右侧文档列表布局；目录与文档的目录归属变更即时生效。
异常
删除目录需二次确认；移动文档失败时文档保留原目录，不产生丢失。
假设 A3：目录本身不设独立授权，目录内文档权限完全随所在知识库；如需目录级授权请指出。
假设 A4：每份文档同一时刻仅归属一个目录；本期目录间仅支持移动，不支持同一文档多目录挂载。

6. 核心流程

6.1 知识库协作建立流程

超管创建用户并赋予"创建知识库"角色 → 用户创建知识库（成为所有者，归属其部门）→ 所有者在成员管理中添加可查看 / 可编辑人员 → 被授权用户在列表中看到该知识库并按层级操作 → 未授权用户全程不可见。

6.2 所有权纠偏流程（离职 / 调岗）

用户离职 → 超管在知识库管理中按所有者筛出其名下知识库 → 逐一强制转移所有权给接手人（原所有者降为可查看人员）→ 全部转移完成后方可删除账号（自动移出各库成员名单）→ 归属部门更新，接管人获得完整控制权。
